SMK routing console

Every button below is an ordinary API call, and the terminal prints the curl for it before it runs. Nothing here is privileged — the console is a face on the contract, not a second way in. What counts as equivalent is decided elsewhere and arrives here as configuration.

Flow A · the partner sends a file

These act as the partner, not as us: each button copies an EDIFACT file into their drop directory and stops. IRIS polls every 5 seconds and finds it on its own.

Flow B · the routing table

One row per operation. Changing a mode changes which implementation answers — no deployment, no consumer change.

Flow B · run the demo

The same four steps as the instructor script, in order.

Resilience · break the shadow backend

In SHADOW the consumer's answer already came from COBOL, so breaking PHP must change nothing anyone outside can see. Put manifest.lookup in SHADOW, break it, then call the contract again.
