JKDM · SMK interoperability POC

One container does the integrating.

Both drawings show the same five containers. The teal boundary is IRIS — everything inside it is one product, installed once. The four boxes below it are the estate being integrated, and three of them are stand-ins for systems JKDM already runs.

Figure 1 — As it ships

Declarations complete the round trip. Manifests are pulled and audited, then rejected — the parser only understands CUSDEC. manifest.lookup sits on LEGACY, so the PHP container is never called for it.

Figure 2 — After the hands-on

No new containers, no new infrastructure. Attendees add a transform inside the existing parser and flip one row in the routing table — and the PHP container starts being called for manifests too.

What the IRIS container provides

Everything in this list is inside the teal boundary and required no additional component. It is the honest answer to "what am I actually buying".

The claim to make in the room is narrow and defensible: fewer moving parts to operate, not "better than the alternatives". API Manager still sits in front of this in the target architecture, Postgres remains the system of record for the declarations, and the fiscal core stays in COBOL — none of that changes.
