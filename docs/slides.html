Flow A 10:45 · 35 min · demo

SFTP is not request/response. IRIS is the client.

There is no inbound call to route. IRIS polls the partner's drop directory and pulls files down. The partner's "push" is them uploading to their own server.

Flow A the order is the architecture

The audit record is written before the parse is attempted.

The file you cannot read is exactly the file you will be asked about.

If a broker says they lodged at 09:14 and the parser rejected it, you need to prove what arrived and when. Parse first, and a bad file leaves you with a stack trace and nothing else.

§2.7 lists audit and non-repudiation as a fabric capability. This is that capability, and it is deliberately boring: create on receipt, update on outcome, never delete.

The defect nobody planted this

One cent, on one declaration, from seven lines of arithmetic.

1088.47COBOL · packed decimal
1088.46PHP · native float
0.01fiscal difference

COBOL

Rounds each line to two decimals in COMP-3, then accumulates.

PHP

Accumulates at full float precision, rounds once at the total.

Why it matters

Neither is a bug in isolation. Both are what a competent developer writes. It took running both against the same data to find it — which is exactly what the §5.7 gate is for.

The second one is worse. A declaration sitting exactly on the 40% local-content threshold: COBOL applies the FTA preference at >=, PHP at >. About RM 600, on a boundary condition nobody wrote a test for.

The join 12:20 · 10 min

File traffic goes through the same routing table as live calls.

An EDIFACT declaration from a partner is lodged over the same API contract a live consumer calls.

So it is shadowed and compared exactly like an interactive request, and the audit trail records which implementation priced it.

This is a decision, not a discovery. §5.2 is silent on whether batch and file-origin traffic get the same dual routing. The POC says yes because it is one line of configuration and it yields evidence from batch traffic too — but JKDM should make that call deliberately.

Open, and staying open

Shadow mode breaks on writes. Everything shadowed today was a calculation — it returns a number and writes nothing. Shadowing a lodgement means writing twice.

  • Shadow reads only — limits what you can prove
  • Isolated shadow schema — doubles data management
  • Compensating transactions — complex, and this is fiscal data
  • Offline replay — loses production realism

Figure 4.3.1 does not address this. There is no clean answer, and it is cheaper to pick one now than in Wave 2.

  • Status code — RL vs RELEASED. Release status is named in the §5.7 fiscal list.

Enablement 16:25 · 30 min

Per-module substitution — the option your own §5.8 already allows.

"…the choice can be confirmed or substituted per module without breaking integrations, and performance-sensitive paths may be isolated behind the same boundary in an alternative approved runtime if assessment requires."

SMK Enterprise & Technical Architecture, §5.8

This segment is not a proposal to change the tender. TS3-02 says PHP and Laravel; TS2-03 and TS3-03 say PostgreSQL. Those stand.

Genuinely stronger

High-throughput ingestion. Anything where the ORM hop is the bottleneck. Mixed operational and analytical access on the same data. One runtime to operate instead of five.

Genuinely weaker

CRUD admin screens, where Laravel is faster to build and cheaper to staff. The §5.8 hiring-pool argument is real — embedded Python narrows it, it does not remove it. And the fiscal core stays in COBOL either way.

Open questions 16:55 · close

Five gaps. None are blockers. All are cheaper to answer now.

  • How does IRIS invoke Visual COBOL? Undecided. Four options with very different latency and transactional characteristics. Today's HTTP wrapper is POC convenience, not a recommendation — and it affects Wave 1 sizing.
  • Does file and batch traffic get strangler routing? §5.2 is silent. The POC says yes.
  • Shadow mode on writes. No clean answer. Pick one before Wave 2.
  • X.400. The §2.7 catalogue records the ECS/EDI DFTZ link as X.400 · SFTP. IRIS speaks SFTP and EDIFACT natively; it does not speak X.400. Needs a gateway or a partner-side change.
  • D96A schemas. IRIS parses EDIFACT structurally but does not ship the UN/EDIFACT message dictionary — those are licensed SEF files. Small cost, real cost, and it must land before the first partner conformance test.
